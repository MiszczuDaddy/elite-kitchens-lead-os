# Calendar views and scheduling

Month, Week, Day and the existing List share one navigation toolbar. A new browser session defaults to Week on desktop (900px and above) and Day on mobile; an explicit view choice is remembered for the session. Today and previous/next move within the current view. Selecting a Month date or Week heading opens Day. Returning from a customer preserves the selected date and view.

Week and Day default to a compact 08:00–20:00 schedule. Desktop hourly rows adjust to viewport height; mobile hourly booking targets remain 44px tall. Desktop has half-hour targets; the existing booking form still supports 15-minute increments on every device. The range automatically expands to include early, late and cross-midnight appointments, and “Show all 24 hours” exposes the entire day. Appointment height represents actual elapsed duration; overlapping appointments occupy separate columns. Clicking an empty slot opens the existing customer chooser and booking form with its date and time prefilled. Arrow keys move between slots; Enter opens booking. Clicking a block opens the existing details dialog, including edit and reschedule actions. Hourly blocks are not draggable. Week can scroll horizontally inside the calendar without widening the page.

All dates use Europe/Dublin. Clock-change days contain 23 or 25 elapsed hours and are labelled; in Week, that day's slots carry their own local-time labels. Nonexistent spring times are absent. The first occurrence of repeated autumn times cannot start a booking, matching the existing backend's choice of the later occurrence. Queries include the prior eight hours (the existing maximum appointment duration) to include visits crossing midnight, using the existing start-time index. Loading, errors and the 500-result cap disable slot booking rather than suggest availability.

Month uses the full available width and shows appointment times and customer names in each date cell. On narrow screens the month scrolls horizontally, keeping readable appointment chips instead of dots. Appointment chips and “+N more” reveal appointments in the agenda below the month. Desktop Month details expand inline; phone and timeline details open in a dialog. Details include appointment type, the customer's home address and budget, internal notes, Google sync state and the existing customer, edit, reschedule and cancel actions.

Expanded appointment details show the linked lead's saved home address and budget. The budget keeps its original wording (including ranges). Missing fields say “Not provided”; loading and read failures have distinct states. A single staff-authorized contact listener follows the currently open appointment and is removed on navigation or sign-out. The separate appointment-location row is omitted for these home consultations. This does not alter existing booking fields or Google Calendar event data.

When Address is blank, a clearly labelled address or Eircode in customer Notes appears automatically, marked “From customer notes”. The customer profile prefills the same value; Save persists it through the existing staff action. Viewing a calendar or profile writes nothing. Existing saved addresses always win. Conflicting, malformed or unclear answers ask staff to check the notes. The parser does not infer from arbitrary prose or turn an Eircode into a street address; it checks format only, following the [Eircode structure](https://www.eircode.ie/what-is-eircode). New Meta imports also fill blank addresses from unambiguous labelled answers while retaining the original notes and preserving staff edits. No existing quote PDF or Google event is changed. Frontend-only rollout supports existing notes; new-import filling additionally requires the updated `leadIntake` function. No backfill or rules migration is needed.

Focused verification: `bash test-ui/run.sh lead-address.e2e.js` runs the shared parser tests, only the address-related intake checks, then the appointment browser checks against demo emulators and fake providers. `functions/lib/leadAddress.js` and its browser copy `public/lead-address.js` must remain identical (checked by the tests).

On desktop with a mouse, drag an appointment chip or agenda entry onto another calendar day to open the reschedule form with that date selected. Irish start time and duration are preserved. The user must confirm the move; closing the form changes nothing. Past dates, unchanged dates, cancelled appointments and external drag data cannot initiate a move. Updates received during the drag are checked before opening the form; subsequent conflicts use the existing expected-version guard. Mobile and keyboard users retain the Reschedule action. For dates outside the visible calendar, use the form's date picker.

“Book appointment” opens a customer chooser using the existing loaded inbox across all stages, then the existing booking dialog with the selected date. Results are capped at 20 until narrowed by name, phone or location. This does not introduce a new customer search backend. Booking from a customer profile still works as before.

All saves use the existing callables, request IDs and expected-version checks. A pending save blocks repeated submission and dismissal. Details-only edits say “Appointment updated”; time changes say “Rescheduled for”. Google remains a one-way copy of Elite OS. Internal notes remain private to Elite OS.

No availability guarantees, free-slot suggestions, business hours, staff assignment, travel calculations or automatic conflict prevention are introduced. Calendar loading failures and the existing 500-result limit are explained in the agenda rather than presented as an empty day.

## Focused checks and local preview

Run `bash test-ui/run.sh appointments.e2e.js` with Node, Java and Playwright/Chrome available. This runs only appointment UI checks using the demo Firebase emulators and a fake Google Calendar.

Run `node --test test-ui/calendar-layout.test.js` for pure date, clock-change, duration, overlap and midnight-boundary checks. The appointment browser checks also cover timeline geometry, slot-prefilled booking, duplicate submission, updating the same Google event, mobile defaults and layouts down to 320px. No new dependencies, backend changes, indexes or migrations are required.

Set `CALENDAR_PREVIEW=1` to keep the local test server and emulators running after the checks pass. Open `http://127.0.0.1:5055/#appointments`; the preview signs into a synthetic demo staff account automatically. It is local to this computer and uses no production customer data. To stop it gracefully in PowerShell, run `Invoke-WebRequest -Method Post -Headers @{'X-Elite-Preview'='stop'} http://127.0.0.1:5055/__stop-preview`. The harness then stops its emulators and removes their temporary configuration files. If the process is force-terminated instead, remove the harness-generated `functions/.env.local` and `functions/.secret.local` before further work.

Screenshots are generated under `test-ui/shots` (or `SHOTS_DIR`). No preview code or automatic login is added to the production frontend.
